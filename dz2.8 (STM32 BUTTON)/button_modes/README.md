# ДЗ 2.8 — button_modes (STM32 BUTTON)

Кнопка перемикає режими світлодіода по колу на **WeAct Black Pill V3.1** зі **STM32F411CEU6**. ESP-IDF тут ні до чого — це STM32 HAL і зовсім інша платформа.

| Стан | Режим | Світлодіод |
|---|---|---|
| старт прошивки | `Off` | не горить |
| 1-ше натискання | `Slow` | блимає з періодом 500 мс — тим самим, що в коді з уроку |
| 2-ге | `Fast` | блимає з періодом 100 мс |
| 3-тє | `Solid` | горить рівно |
| 4-те | `Off` | не горить, цикл замикається |

Режим перемикає натискання, а не відпускання.

## Чому код з уроку не можна просто доповнити

На занятті було так:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(500);
```

Напрошується дописати сюди читання піна:

```c
while (1) {
    if (HAL_GPIO_ReadPin(BUTTON_GPIO_Port, BUTTON_Pin) == GPIO_PIN_RESET) { /* ... */ }
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    HAL_Delay(500);   // <- тут усе й ламається
}
```

`HAL_Delay()` — це не пауза, а порожній цикл очікування:

```c
while ((HAL_GetTick() - tickstart) < wait) { }
```

Поки він крутиться, читати пін нема кому. Кнопку буде опитано **раз на 500 мс**, і натискання, яке почалося й закінчилось між двома опитуваннями, прошивка не побачить узагалі. Навіть спіймане натискання відпрацює із запізненням до пів секунди.

Тому `HAL_Delay()` тут немає взагалі. Замість нього — сітка на `HAL_GetTick()`, той самий прийом, що `millis()` у [ДЗ 2.3](../../dz2.3%20%28SUPERLOOP%29/three_leds/):

```cpp
if (blink_ms != 0 && now - last_toggle >= blink_ms) {
    last_toggle += blink_ms;
    led_on = !led_on;
    led_write(led_on);
}
```

Цикл ніде не блокується, тож пін читається на кожній ітерації, а не раз на період блимання. Швидкість реакції задає вже не блимання, а витримка debounce.

Альтернатива — переривання EXTI на PA0. Вона тут нічого не додала б: брязкіт однаково довелося б гасити, а цикл і так вільний. Опитування в незаблокованому циклі — не компроміс, а достатнє рішення для цієї задачі.

## Режими — таблиця

```cpp
static constexpr ModeDef MODES[MODE_COUNT] = {
  { Mode::Off,   0,                false },
  { Mode::Slow,  Config::SLOW_MS,  false },
  { Mode::Fast,  Config::FAST_MS,  false },
  { Mode::Solid, 0,                true  },
};
```

Один рядок — один режим: період блимання і стан світлодіода, коли він не блимає. Нуль у `blink_ms` означає «не блимає», і тоді працює поле `lit`. Додати режим — додати рядок.

Поле `self` дублює індекс, щоб перестановку рядків спіймав компілятор. Три `static_assert` стежать за таблицею: порядок рядків, `FAST_MS < SLOW_MS`, і що витримка debounce коротша за найшвидше блимання — інакше натискання могло б загубитися між двома перемиканнями.

## Брязкіт

Витримка по рівню: рівень має протриматися незмінним 20 мс, і лише тоді вважається станом кнопки.

```cpp
if (level != last_level) {
    last_level = level;
    last_edge  = now;          // лінія смикнулась — відлік тиші спочатку
} else if (now - last_edge >= Config::DEBOUNCE_MS) {
    // рівень стабільний, тепер він щось означає
}
```

Це метод `state_debounce` із [ДЗ 2.4](../../dz2.4%20%28BUTTON%20DEBOUNCE%29/state_debounce/), перенесений один в один. Режим перемикає натискання, не відпускання.

## Дві пастки, на які можна втратити вечір

**`SysTick_Handler` треба оголосити самому.** PlatformIO з `framework = stm32cube` не кладе згенерований `stm32f4xx_it.c`, тож обробника системного таймера в проєкті немає, і спрацьовує слабка заглушка з `startup_*.s` — нескінченний цикл. Наслідок тихий і неприємний: `HAL_GetTick()` назавжди лишається нулем, а `HAL_Delay()` не повертається ніколи.

```cpp
extern "C" void SysTick_Handler(void)
{
    HAL_IncTick();
}
```

`extern "C"` обов'язковий: ім'я має точно збігтися з тим, що в таблиці векторів, а C++ без обгортки його спотворив би. Перевірити, що вийшло, можна прямо в `.elf` — у слоті SysTick (зсув `0x3C`) має стояти адреса твоєї функції, а не `Default_Handler`:

```sh
arm-none-eabi-objdump -s -j .isr_vector .pio/build/stm32_button_modes/firmware.elf
```

**`HAL_GetTick()` перевертається через 49,7 доби.** Тому всі порівняння часу тут — різницею беззнакових (`now - last_edge >= DEBOUNCE_MS`), а не `now >= deadline`. Різниця переживає перевертання правильно, пряме порівняння — ні.

## Тактування

HSI 16 МГц, без PLL. F411CE вміє 100 МГц і на платі стоїть кварц HSE 25 МГц, але для блимання й кнопки це нічого не дає, а HSI має дві переваги: конфігурація тримається однаковою для всієї трійки Black Pill (межі PLL у F401 і F411 різні — 84 і 100 МГц), і в неї нема чому не запуститися. Невдалий старт HSE завершився б у `Error_Handler()`, і плата виглядала б мертвою. На 16 МГц флеш читається з `FLASH_LATENCY_0`.

Якщо знадобиться більше — міняється лише `SystemClock_Config()`, решта коду від частоти не залежить: `HAL_GetTick()` однаково тикає раз на мілісекунду, бо `HAL_InitTick()` рахує дільник від `SystemCoreClock`.

## Чому C++, якщо HAL — це C

З тієї ж причини, що в [ДЗ 2.6](../../dz2.6%20%28ESP-IDF%20DEBOUNCE%29/#чому-прошивки-на-c-хоч-esp-idf--це-c): щоб стиль по репозиторію не розсипався — `struct Config` зі `static constexpr`, `enum class`, таблиця з `static_assert`. Хедери HAL про C++ знають самі, у них стоять `extern "C"` обгортки. Єдине місце, де про це треба пам'ятати, — обробники переривань: їх C++ спотворив би, тому `SysTick_Handler` загорнутий явно.

## Схема

Нічого паяти не треба — світлодіод і кнопка вже на платі:

| | Пін | Примітка |
|---|---|---|
| Світлодіод | PC13 | катод на пін, анод через резистор на 3,3 В — **горить від низького рівня** |
| Кнопка KEY | PA0 | замикає пін на землю, підтяжка внутрішня `GPIO_PULLUP` |

Якщо кнопка поводиться навпаки — на твоїй ревізії плати вона може бути заведена інакше; міняється одна константа `Config::BUTTON_PRESSED`.

## Запуск

Прошивка через **ST-LINK V2**, чотири проводи на SWD-гребінку плати:

| ST-LINK | Black Pill |
|---|---|
| SWDIO | SWDIO (DIO) |
| SWCLK | SWCLK (CLK) |
| GND | GND |
| 3.3V | 3V3 |

```sh
pio run -e stm32_button_modes -t upload
```

Окремий `openocd` чи `st-flash` ставити не треба — PlatformIO тягне готові бінарники сам.

У [`platformio.ini`](../../platformio.ini) стоїть `board = blackpill_f411ce` — чіп прочитаний із маркування. Код від моделі не залежить: збірка проходить також під `blackpill_f401cc` і `blackpill_f401ce`.
