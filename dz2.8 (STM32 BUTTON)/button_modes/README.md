# ДЗ 2.8 — button_modes (STM32 BUTTON)

Прошивка для **WeAct Black Pill V3.1** зі **STM32F411CEU6** на STM32 HAL. Кнопка KEY перемикає режими світлодіода по колу.

| Стан | Режим | Світлодіод |
|---|---|---|
| старт прошивки | `Off` | не горить |
| 1-ше натискання | `Slow` | блимає з періодом 500 мс, як у коді з уроку |
| 2-ге натискання | `Fast` | блимає з періодом 100 мс |
| 3-тє натискання | `Solid` | горить постійно |
| 4-те натискання | `Off` | не горить |

Режим перемикає момент натискання. Відпускання кнопки режим не змінює.

## Чому код з уроку не підходить

Код з уроку блимає так:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(500);
```

Перша ідея — додати читання піна в той самий цикл:

```c
while (1) {
    if (HAL_GPIO_ReadPin(BUTTON_GPIO_Port, BUTTON_Pin) == GPIO_PIN_RESET) { /* ... */ }
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    HAL_Delay(500);   // <- тут усе й ламається
}
```

`HAL_Delay()` виконує порожній цикл:

```c
while ((HAL_GetTick() - tickstart) < wait) { }
```

Протягом цього циклу прошивка не читає пін. Тоді прошивка опитує кнопку раз на 500 мс. Коротке натискання між двома опитуваннями прошивка не помітить. Навіть помічене натискання спрацює із затримкою до 500 мс.

Тому прошивка не викликає `HAL_Delay()`. Час рахує сітка на `HAL_GetTick()`, як `millis()` у [ДЗ 2.3](../../dz2.3%20%28SUPERLOOP%29/three_leds/):

```cpp
if (blink_ms != 0 && now - last_toggle >= blink_ms) {
    last_toggle += blink_ms;
    led_on = !led_on;
    led_write(led_on);
}
```

Цикл не блокується, і прошивка читає пін на кожній ітерації. Час реакції тепер задає debounce, а період блимання на нього не впливає.

Переривання EXTI на PA0 тут нічого не дає. Брязкіт контактів однаково треба придушувати, а цикл і так вільний. Для цієї задачі опитування в циклі без блокування достатньо.

## Таблиця режимів

```cpp
static constexpr ModeDef MODES[MODE_COUNT] = {
  { Mode::Off,   0,                false },
  { Mode::Slow,  Config::SLOW_MS,  false },
  { Mode::Fast,  Config::FAST_MS,  false },
  { Mode::Solid, 0,                true  },
};
```

Один рядок описує один режим. Поле `blink_ms` задає період блимання. Значення 0 означає, що світлодіод не блимає, і тоді його стан задає поле `lit`. Щоб додати режим, додайте рядок.

Поле `self` повторює індекс рядка. Якщо рядки переставити, компілятор покаже помилку.

Три `static_assert` перевіряють таблицю:
- порядок рядків збігається з `enum class Mode`;
- `FAST_MS` менший за `SLOW_MS`;
- debounce коротший за найшвидше блимання, інакше натискання може загубитися між двома перемиканнями.

## Брязкіт контактів

Прошивка приймає рівень як стан кнопки тільки після 20 мс без змін:

```cpp
if (level != last_level) {
    last_level = level;
    last_edge  = now;          // лінія смикнулась — відлік тиші спочатку
} else if (now - last_edge >= Config::DEBOUNCE_MS) {
    // рівень стабільний, тепер він щось означає
}
```

Метод `state_debounce` перенесено з [ДЗ 2.4](../../dz2.4%20%28BUTTON%20DEBOUNCE%29/state_debounce/) без змін.

## Дві пастки

Перша пастка: `SysTick_Handler` треба оголосити в прошивці. PlatformIO з `framework = stm32cube` не додає файл `stm32f4xx_it.c`. Тоді спрацьовує заглушка зі `startup_*.s`, яка є нескінченним циклом. `HAL_GetTick()` завжди повертає 0, а `HAL_Delay()` ніколи не завершується.

```cpp
extern "C" void SysTick_Handler(void)
{
    HAL_IncTick();
}
```

`extern "C"` обов'язковий. Ім'я функції має точно збігатися з ім'ям у таблиці векторів, а компілятор C++ змінює імена функцій.

Щоб перевірити результат, прочитайте таблицю векторів з `.elf`:

```sh
arm-none-eabi-objdump -s -j .isr_vector .pio/build/stm32_button_modes/firmware.elf
```

У слоті SysTick (зсув `0x3C`) має бути адреса `SysTick_Handler` з прошивки. Адреса `Default_Handler` означає помилку.

Друга пастка: лічильник `HAL_GetTick()` переповнюється через 49,7 доби. Тому прошивка порівнює час різницею беззнакових чисел: `now - last_edge >= DEBOUNCE_MS`. Після переповнення різниця дає правильний результат, а порівняння `now >= deadline` — неправильний.

## Тактування

Прошивка працює від HSI 16 МГц без PLL. F411CE підтримує 100 МГц, а на платі є кварц HSE 25 МГц. Для світлодіода й кнопки висока частота не потрібна.

HSI має дві переваги:
- одна конфігурація працює на всіх трьох моделях Black Pill. Для PLL це неможливо: межі F401 і F411 різні, 84 і 100 МГц.
- HSI завжди запускається, а помилка старту HSE переводить прошивку в `Error_Handler()`.

На 16 МГц флеш працює з `FLASH_LATENCY_0`.

Щоб збільшити частоту, змініть тільки `SystemClock_Config()`. Решта коду від частоти не залежить. `HAL_InitTick()` рахує дільник від `SystemCoreClock`, тому `HAL_GetTick()` завжди рахує мілісекунди.

## Чому C++

HAL написано на C, а прошивку — на C++, як решту репо. Код використовує `struct Config` зі `static constexpr`, `enum class` і таблицю з `static_assert`. Причина та сама, що в [ДЗ 2.6](../../dz2.6%20%28ESP-IDF%20DEBOUNCE%29/#чому-прошивки-на-c-хоч-esp-idf--це-c).

Заголовки HAL уже мають обгортки `extern "C"`. Обгортку треба додати тільки для обробників переривань, тому `SysTick_Handler` має `extern "C"`.

## Схема

Світлодіод і кнопка вже є на платі:

| Елемент | Пін | Примітка |
|---|---|---|
| світлодіод | PC13 | катод на піні, анод через резистор на 3,3 В; світлодіод горить від низького рівня |
| кнопка KEY | PA0 | кнопка з'єднує пін із GND, внутрішня підтяжка до живлення `GPIO_PULLUP` |

Якщо кнопка працює навпаки, змініть константу `Config::BUTTON_PRESSED`. На іншій ревізії плати кнопку можуть підключити інакше.

## Запуск

1. Підключіть ST-LINK V2 до SWD-роз'єму плати:

   | ST-LINK | Black Pill |
   |---|---|
   | SWDIO | SWDIO (DIO) |
   | SWCLK | SWCLK (CLK) |
   | GND | GND |
   | 3.3V | 3V3 |

2. Зберіть і прошийте прошивку:
   ```sh
   pio run -e stm32_button_modes -t upload
   ```

PlatformIO сам завантажує `openocd`. Окремо встановлювати `openocd` чи `st-flash` не треба.

У [`platformio.ini`](../../platformio.ini) задано `board = blackpill_f411ce`, як у маркуванні чіпа. Код від моделі не залежить: прошивка також збирається під `blackpill_f401cc` і `blackpill_f401ce`.
