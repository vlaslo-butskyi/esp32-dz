# ДЗ 2.8 — button_modes_uart (STM32 BUTTON)

Ця прошивка повторює [`button_modes`](../button_modes/) і додає текстовий лог у USART1. Лог показує, що прошивка робить з кнопкою. Відповідь на умову — прошивка `button_modes`.

## Чому потрібен окремий варіант

Ця плата не має послідовного порту для монітора:
- USB-C плати підключено до пінів USB мікроконтролера (PA11, PA12). Комп'ютер не побачить пристрій, поки прошивка сама не запустить USB CDC.
- Синій ST-LINK V2 не має віртуального COM-порту (VCP). VCP є тільки в ST-LINK V2-1 і V3 на платах Nucleo й Discovery.

Тому прошивка пише лог у USART1 на пін PA9.

## Як лог працює без блокування

`HAL_UART_Transmit()` чекає, поки UART передасть увесь рядок. Кожен рядок займає кілька мілісекунд. При debounce 20 мс трьох рядків досить, щоб пропустити натискання.

Тому прошивка записує рядки в кільцевий буфер. Наприкінці кожної ітерації `log_pump()` передає в UART не більше одного байта:

```cpp
if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_TXE) == RESET) {
    return;                      // передавач зайнятий — зайдемо наступної ітерації
}
huart1.Instance->DR = static_cast<uint8_t>(log_buf[log_tail]);
```

Якщо передавач зайнятий, `log_pump()` повертається одразу. Якщо буфер переповнений, прошивка відкидає нові байти й не чекає. Потім прошивка пише в лог кількість відкинутих байтів.

## Як прочитати лог

| Black Pill | Перехідник USB-UART | Логічний аналізатор |
|---|---|---|
| PA9 (TX) | RX | будь-який канал |
| GND | GND | GND |

Через перехідник USB-UART (CP2102, CH340 або FTDI):

1. Підключіть PA9 до RX перехідника, GND до GND.
2. Відкрийте монітор порту:
   ```sh
   pio device monitor -e stm32_button_modes_uart
   ```

Прошивка тільки передає дані, а RX плати не підключено. Тому узгодження рівнів не потрібне.

Через логічний аналізатор:

1. Підключіть канал аналізатора до PA9.
2. У Logic 2 додайте до каналу аналізатор Async Serial.
3. Задайте параметри: 115200 бод, 8 біт, без парності, 1 стоп-біт.

Другий канал можна підключити до PA0. Тоді аналізатор покаже брязкіт контактів поряд з реакцією прошивки.

## Що в логу

```
=== dz2.8 button_modes_uart ===
clock 16000000 Hz, debounce 20 ms, slow 500 ms, fast 100 ms
start mode Off, press KEY on PA0

[   4312 ms] edge 0
[   4313 ms] edge 1
[   4313 ms] edge 0
[   4333 ms] press #1 -> Slow (blink 500 ms), edges filtered: 3
[   4474 ms] edge 1
[   4494 ms] release
```

| Запис | Значення |
|---|---|
| `edge 0`, `edge 1` | фронт або спад на піні, як його прочитала прошивка |
| `edges filtered` | кількість фронтів і спадів, які debounce відкинув до одного натискання |
| час у дужках | `HAL_GetTick()`, мілісекунди від старту |

Значення `edges filtered` 1 означає кнопку без брязкоту. Значення від 5 до 15 означає звичайний брязкіт контактів.

Якщо час завжди 0, `SysTick_Handler` не працює. Цю пастку описано в [README `button_modes`](../button_modes/).

## Запуск

Зберіть і прошийте прошивку:

```sh
pio run -e stm32_button_modes_uart -t upload
```

UART бере тактування від HSI 16 МГц. Точність HSI становить ±1 %, а дільник додає похибку 0,08 %. Цього запасу досить для 115200 бод.

Якщо монітор показує випадкові символи, плата могла нагрітися. Тоді змініть `SystemClock_Config()` на HSE з PLL.

## Відмінності від button_modes

| | `button_modes` | `button_modes_uart` |
|---|---|---|
| автомат режимів | однаковий | однаковий |
| debounce | однаковий | однаковий |
| USART1 на PA9 | немає | 115200 8N1, тільки передача |
| кільцевий буфер логу | немає | 512 байт |
| RAM / Flash | 44 Б / 3524 Б | 636 Б / 4876 Б |
