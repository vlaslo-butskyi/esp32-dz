# ДЗ 2.9 — `setup()` і `loop()` в окремих файлах (SETUP LOOP)

Цей документ описує другу домашку гнучкого слоту. Прошивка блимає світлодіодом, а код блимання винесено з `main.c` у функції `setup()` і `loop()`.

| Параметр | Значення |
|---|---|
| плата | WeAct Black Pill V3.1, мікроконтролер STM32F411CEU6, як у ДЗ 2.8 |
| бібліотека | STM32 HAL |
| збірка | PlatformIO, `framework = stm32cube` |
| прошивання | ST-LINK V2 через SWD |

Для уроку 2.9 є тільки умова, коду з уроку немає. Код блимання взято з CubeIDE-проєкту заняття 2.8. У `main.c` між `/* USER CODE BEGIN 3 */` і `/* USER CODE END 3 */` був такий код:

```c
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(BLINK_INTERVAL_MS);
```

| Папка | Опис |
|---|---|
| [`blink`](blink/) | прошивка |
| [`guard`](guard/) | приклад до опційного пункту умови; компілятор комп'ютера збирає його окремо від прошивки |

## Як поділено файли

| Файл | Рівень | Вміст |
|---|---|---|
| [`blink/main.c`](blink/main.c) | платформа | `HAL_Init()`, тактування, `SysTick_Handler`, `Error_Handler`, `main()` |
| [`blink/app.c`](blink/app.c) | прикладний | піни, полярність, період, налаштування GPIO, перемикання рівня |
| [`blink/app.h`](blink/app.h) | межа між ними | `setup()`, `loop()` і сторожа заголовка |

Після розділення `main()` має таку саму структуру, як в Arduino:

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();

    setup();

    while (1) {
        loop();
    }
}
```

Межа між файлами відповідає на питання: чи знає цей рядок, яким світлодіодом керує прошивка. У `main.c` немає `GPIOC`, `GPIO_PIN_13` і 500 мс. `app.c` не знає про тактування і про те, яка функція його викликає.

`setup()` один раз налаштовує пін. `loop()` перемикає рівень на кожному проході. Код з уроку перенесено без змін, бо умова вимагає розділити файли, а код залишити.

## STM32 і VS Code

Умова згадує VS Code. Редактор — VS Code, а збірка така сама, як у всьому репо: `pio run`. CubeIDE тут не потрібен.

У цій збірці немає генератора CubeMX. Файл `main.c` написано вручну, і генератор його не перезаписує.

У згенерованому проєкті окремий файл для коду блимання дає найбільшу користь. CubeMX при кожній генерації перезаписує `main.c`. Генератор видаляє весь код поза блоками `USER CODE`. Код в окремому файлі від генерації не залежить.

Тут генератора немає, але структура до нього готова. Файли `app.c` і `app.h` можна перенести в CubeMX-проєкт без змін. Змінити треба тільки `main.c`.

Розділення має й інші переваги:
- `app.c` не знає про тактування, тому файл можна перенести на іншу плату;
- `main.c` короткий, і його можна прочитати за 10 секунд.

## Сторожа заголовка

`app.h` має класичну сторожу заголовка: `#ifndef`, `#define`, `#endif`. Ім'я макросу містить номер домашки. Якщо два заголовки мають однакове ім'я `APP_H`, другий заголовок перетворюється на порожній текст.

`#pragma once` робить те саме одним рядком. Але цієї директиви немає ні в C23, ні в C++, це розширення компіляторів. Директива покладається на те, що компілятор упізнає файл. Через символьні посилання компілятор іноді його не впізнає.

Друга частина механізму — `extern "C"` під `#ifdef __cplusplus`. Решта репо написана на C++. Без цієї обгортки файл `.cpp` не зможе викликати функції з `app.h`. У ДЗ 2.8 цю проблему розв'язано тільки для `SysTick_Handler` у `main.cpp`.

Сторожа не розриває циклічну залежність між двома заголовками. Вона тільки зупиняє нескінченний `#include` у препроцесорі. Заголовок, який `#include` додав другим, стає порожнім текстом, і компілятор не бачить потрібного типу. Цикл розриває оголошення наперед. Приклад — у [`guard/`](guard/).

## Збірка

Зберіть і прошийте прошивку:

```sh
pio run -e stm32_app_blink -t upload
```

| Параметр | Значення |
|---|---:|
| Flash | 3360 Б |
| RAM | 44 Б |

Середовище в [`platformio.ini`](../platformio.ini) наслідує базову секцію `[stm32]`, як обидва середовища з ДЗ 2.8. Прошивка складається з двох файлів `.c`, тому фільтр містить шаблон: `+<../dz2.9 (SETUP LOOP)/blink/*.c>`.

Параметр `-I` для `app.h` не потрібен. Директива `#include "..."` спочатку шукає файл у каталозі файлу, який її містить.

Приклад зі сторожею не потребує STM32. Запустіть його з кореня репо:

```sh
"./dz2.9 (SETUP LOOP)/guard/run.sh"
```

## Що ще не перевірено

- Прошивку зібрано, але ще не записано на плату. Треба перевірити, що період блимання такий самий, як до розділення.
- Фото плати ще не зроблено.
