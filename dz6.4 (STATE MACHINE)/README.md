# ДЗ 6.4 — кінцевий автомат (STATE MACHINE)

Цей документ описує ДЗ 6.4. Умова: написати кінцевий автомат електронного сейфа (Consumer), який отримує події від автомата кнопки (Producer). Пароль: коротке, коротке, довге натискання.

| Прошивка | Плата | Опис |
|---|---|---|
| [`safe_fsm`](safe_fsm/) | ESP32-S3-DevKitC-1 | відповідь на умову, ESP-IDF |
| [`safe_fsm_stm32`](safe_fsm_stm32/) | WeAct Black Pill, STM32F411 | та сама прошивка на STM32 HAL і FreeRTOS 10.3.1, поза умовою |

## Як прошивка виконує умову

| Вимога умови | Рішення в прошивці |
|---|---|
| одна кнопка | GPIO 16 на ESP32, KEY (PA0) на STM32, задача `button` опитує її кожні 10 мс |
| Producer | автомат кнопки `button`: події `PRESS`, `SHORT`, `LONG` |
| Consumer | автомат сейфа `safe`: стани `LOCKED`, `SHORT_1`, `SHORT_2`, `OPEN` |
| пароль `S S L` | `LOCKED`, потім `SHORT_1`, потім `SHORT_2`, потім `OPEN` |
| помилка скидає автомат | неправильна подія в будь-якому стані веде в `LOCKED` |
| 3 с без натискань скидають автомат | `xQueueReceive` з таймаутом, подія `TIMEOUT` веде в `LOCKED` |

## Типові помилки з умови

| Помилка | Рішення в прошивці |
|---|---|
| таймаут скидає автомат, поки кнопку утримують | подія `PRESS` перезапускає таймаут |
| час через `==` при кроці 10 мс | різниця тіків і порівняння через `>=` |
| `hold_time += 10` замість реального часу | `xTaskGetTickCount` і `vTaskDelayUntil` |
| відпускання без debounce | debounce 30 мс для натискання і для відпускання |
| магічні числа й `#define` | усі числа в `struct Config` як `static constexpr` |
| успішне відкриття через `ESP_LOGE` | відкриття через `ESP_LOGI`, помилка і таймаут через `ESP_LOGW` |

Обидві прошивки перевірено на платах, ESP32-версію також у симуляторі Wokwi. Таблицю переходів автомата сейфа перевіряє `static_assert` під час збірки. Подробиці описано в README прошивки.
