# ДЗ 6.4 — safe_fsm_stm32 (STATE MACHINE)

Прошивка для **WeAct Black Pill V3.1** зі **STM32F411CEU6**. Прошивка відкриває електронний сейф, коли користувач вводить пароль кнопкою KEY: коротке, коротке, довге натискання. Автомати кнопки й сейфа спільні з прошивкою [`safe_fsm`](../safe_fsm/) для ESP32-S3: обидві збирають файли з [`../common`](../common/).

| Задача | Роль з умови | Що робить |
|---|---|---|
| `button` | Producer | автомат кнопки: опитує KEY кожні 10 мс і кладе в чергу події `PRESS`, `SHORT`, `LONG` |
| `safe` | Consumer | автомат сейфа: читає чергу, перемикає стан, керує світлодіодом і пише лог |

## Підключення

| Компонент | Пін Black Pill | Примітка |
|---|---|---|
| кнопка KEY | PA0 | кнопка на платі, підключати нічого не треба |
| світлодіод плати | PC13 | горить, поки сейф відкритий |
| перехідник CH340, RXD | A9 (PA9) | USART1_TX, лог 115200 бод |
| перехідник CH340, GND | G | |
| ST-LINK V2 | SWD: 3V3, SWDIO, SWCLK, GND | прошивка й перезапуск |

Світлодіод плати горить від низького рівня на PC13. TXD перехідника не підключайте.

## Відмінності від ESP32-версії

| | ESP32-S3 | STM32F411 |
|---|---|---|
| кнопка | зовнішня, GPIO 16 | KEY на платі, PA0 |
| світлодіод | зовнішній, GPIO 4, горить від 1 | на платі, PC13, горить від 0 |
| лог | `ESP_LOGI`, `ESP_LOGW` у консоль ESP-IDF | `log_line()`: `HAL_UART_Transmit` під м'ютексом, формат як в ESP-IDF |
| пріоритети | `button` 5, `safe` 4, обидві на ядрі 1 | `button` 3, `safe` 2, ядро одне |
| стек задачі | 3072 байти | 256 слів, тобто 1024 байти |
| налаштування FreeRTOS | `sdkconfig.defaults` | [`FreeRTOSConfig.h`](FreeRTOSConfig.h) |

Файли: [`main.c`](main.c) і спільні автомати в [`../common`](../common/). Діаграми станів, таблицю переходів і тести на ПК описує [README спільних автоматів](../common/). `main.c` містить тільки HAL, чергу, задачі, SysTick і лог. Задачі `button_task` і `safe_task` мають ту саму будову, що в ESP32-версії.

`HAL_UART_Transmit` блокує задачу `safe` на кілька мілісекунд на кожен рядок. Тому `safe` вмикає світлодіод до запису в лог. Задача `button` має вищий пріоритет, тому лог не зсуває опитування кнопки.

Піни задано як `static const`, числові параметри задає `enum`, без `#define`.

## Лог плати

ST-LINK перезапустив плату, перехідник CH340 записав лог за 100 с. Лог записала перша версія прошивки на C++, до перенесення автоматів у `common`. Кнопку KEY натискала людина: 38 натискань у різних комбінаціях. Повний лог: [`serial.log`](serial.log).

| Показник | Результат |
|---|---|
| події | 38 `PRESS`, 27 `SHORT`, 11 `LONG`, 3 `TIMEOUT` |
| відкриття сейфа | 5, з них 3 закрило `SHORT` і 2 закрив таймаут 5000 мс |
| `wrong input` | 9 |
| `input timeout` | 1, через 3000 мс після `SHORT` |
| тривалість `SHORT` | від 130 до 610 мс |
| переходи, які не збіглися з таблицею | 0 з 79 |

Скрипт перевірив кожен рядок лога. Початковий стан рядка збігся з кінцевим станом попереднього рядка. Кожна пара «стан, подія» дала стан з таблиці переходів.

Фрагмент лога:

```
I (46621) safe: PRESS            LOCKED
I (46791) safe: SHORT    170 ms  LOCKED -> SHORT_1
W (49791) safe: TIMEOUT 3000 ms  SHORT_1 -> LOCKED, input timeout
I (50991) safe: PRESS            LOCKED
W (51961) safe: LONG    1000 ms  LOCKED -> LOCKED, wrong input
I (57761) safe: PRESS            LOCKED
I (57911) safe: SHORT    150 ms  LOCKED -> SHORT_1
I (58091) safe: PRESS            SHORT_1, timer restarted
I (58271) safe: SHORT    180 ms  SHORT_1 -> SHORT_2
I (59831) safe: PRESS            SHORT_2, timer restarted
I (60801) safe: LONG    1000 ms  SHORT_2 -> OPEN, safe is open
I (65801) safe: TIMEOUT 5000 ms  OPEN -> LOCKED, safe is closed
```

У цьому лозі `LONG` у всіх 5 відкриттях прийшов не пізніше ніж через 2530 мс після `SHORT`. Тому лог не перевіряє перезапуск таймауту через `PRESS`. Цей випадок перевірено на ESP32-версії з тим самим кодом автоматів.

## Запуск

1. Підключіть ST-LINK V2 до SWD-роз'єму плати.
2. Підключіть PA9 до RXD перехідника CH340, GND до GND.
3. Прошийте плату:
   ```sh
   pio run -e stm32_safe_fsm -t upload
   ```
4. Відкрийте монітор порту:
   ```sh
   pio device monitor -e stm32_safe_fsm
   ```
