# ДЗ 6.5 — м'ютекси і семафори (MUTEX SEMAPHORE)

Цей документ описує ДЗ 6.5. Умова: конвеєр на двох ядрах ESP32-S3. ISR лічить деталі, дві задачі пишуть звіт у спільний буфер, кнопка аварійної зупинки зупиняє конвеєр.

| Прошивка | Плата | Опис |
|---|---|---|
| [`conveyor`](conveyor/) | ESP32-S3-DevKitC-1 | відповідь на умову, ESP-IDF |

## Як прошивка виконує умову

| Вимога умови | Рішення в прошивці |
|---|---|
| кнопка 1 імітує оптичний датчик | GPIO 16, ISR `part_isr` на обох фронтах, debounce 30 мс тиші |
| ISR збільшує глобальний лічильник | `parts = parts + 1` під спінлоком `parts_lock` |
| інші задачі читають лічильник | `read_parts()` під тим самим спінлоком |
| Task 1 на ядрі 0 раз на секунду рахує деталі/хв | `report`, `vTaskDelayUntil` 1000 мс, швидкість за 10 с |
| Task 2 на ядрі 1 раз на секунду читає АЦП | `adc`, потенціометр на GPIO 1, після кожного звіту Task 1 |
| один спільний буфер звіту | `report_text[64]` під м'ютексом `report_mutex`, Take з таймаутом 100 мс |
| Task 2 дописує в той самий буфер | бінарний семафор `report_ready` задає порядок: спершу Task 1, потім Task 2 |
| кнопка 2 викликає ISR | BOOT (GPIO 0), ISR `stop_isr` дає семафор `stop_signal` |
| Task 3 з найвищим пріоритетом спить без витрат CPU | `estop`, пріоритет 10, `xSemaphoreTake(stop_signal, portMAX_DELAY)` |
| Task 3 прокидається миттєво | `portYIELD_FROM_ISR`: 21 мкс від ISR до задачі на платі |
| Task 3 вмикає світлодіод | GPIO 4 |
| Task 3 безпечно пише `SYSTEM HALTED!` | під `report_mutex`; `report` і `adc` перевіряють `halted` під тим самим м'ютексом |
| Task 3 блокує роботу конвеєра | переривання датчика вимкнено, `report` і `adc` видаляють себе |

Прошивку перевірено на платі і в симуляторі Wokwi. На платі 30 натискань кнопки-датчика дали `parts 30`. Подробиці описано в README прошивки.
