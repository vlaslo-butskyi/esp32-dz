# ДЗ 6.5 — conveyor_stm32 (MUTEX SEMAPHORE)

Прошивка для **WeAct Black Pill V3.1** зі **STM32F411CEU6**. Прошивка лічить деталі, раз на секунду складає звіт у спільний буфер і зупиняє конвеєр кнопкою KEY. Задачі, ISR і порядок аварійної зупинки такі самі, як у прошивці [`conveyor`](../conveyor/) для ESP32-S3.

| Виконавець | Пріоритет | Що робить |
|---|---|---|
| `part_isr` | EXTI15_10, 6 | датчик деталі на PB12: додає 1 до лічильника `parts` |
| `stop_isr` | EXTI0, 6 | аварійна зупинка KEY: дає семафор `stop_signal` |
| `report` (Task 1) | 2 | раз на секунду читає `parts`, рахує швидкість і пише початок звіту |
| `adc` (Task 2) | 2 | читає АЦП і дописує напругу в той самий буфер звіту |
| `estop` (Task 3) | 4 | чекає на `stop_signal`, потім зупиняє конвеєр |

## Підключення

| Компонент | Пін Black Pill | Примітка |
|---|---|---|
| тактова кнопка, датчик деталі | B12 (PB12) | другий контакт на GND, внутрішня підтяжка до живлення |
| кнопка KEY, аварійна зупинка | PA0 | кнопка на платі, підключати нічого не треба |
| світлодіод плати, тривога | PC13 | на платі, горить від низького рівня |
| потенціометр, повзунок | A1 (PA1) | крайні виводи на 3V3 і G |
| перехідник CH340, RXD | A9 (PA9) | USART1_TX, лог 115200 бод |
| перехідник CH340, GND | G | |
| ST-LINK V2 | SWD: 3V3, SWDIO, SWCLK, GND | прошивка й перезапуск |

TXD перехідника не підключайте.

## Відмінності від ESP32-версії

| | ESP32-S3 | STM32F411 |
|---|---|---|
| ядра | 2: `report` на ядрі 0, `adc` на ядрі 1 | 1: `report` і `adc` працюють по черзі |
| захист `parts` | спінлок `portENTER_CRITICAL` | `taskENTER_CRITICAL`, маскує переривання з пріоритетом від 5 до 15 |
| час у `part_isr` | `esp_timer_get_time()`, мкс | `xTaskGetTickCountFromISR()`, мс |
| затримка ISR -> `estop` | `esp_timer_get_time()` | лічильник тактів DWT, 62,5 нс на такт |
| АЦП | калібрування eFuse, curve fitting | VDDA з VREFINT і `VREFINT_CAL` |
| лог | `ESP_LOGx`, консоль ESP-IDF | `log_line()`: `HAL_UART_Transmit` під своїм м'ютексом |
| пріоритети | `report` і `adc` 5, `estop` 10 | `report` і `adc` 2, `estop` 4 |
| м'ютекс і семафори | `...CreateStatic` | `xSemaphoreCreateMutex`, `xSemaphoreCreateBinary` |
| налаштування FreeRTOS | `sdkconfig.defaults` | [`FreeRTOSConfig.h`](FreeRTOSConfig.h) |

Фільтр брязкоту, розрахунок швидкості і текст звіту спільні з ESP32-версією: обидві прошивки збирають файли з [`../common`](../common/). Опис коду, діаграму послідовності і порядок аварійної зупинки дивіться в [README ESP32-версії](../conveyor/).

На одному ядрі задачі не звертаються до буфера фізично одночасно. Але планувальник може перемкнути задачу посередині `memcpy`. Тому `report_mutex` потрібен і тут.

### Два м'ютекси

Прошивка має два м'ютекси: `report_mutex` для буфера звіту і `uart_mutex` для USART1. Задача ніколи не тримає обидва одночасно. `adc` копіює буфер, віддає `report_mutex` і тільки потім викликає `log_line()`. Так одна з умов deadlock, циклічне очікування, не може виникнути.

### Успадкування пріоритету

Прошивка використовує нативний API FreeRTOS, а не CMSIS-OS v2. `xSemaphoreCreateMutex` завжди створює м'ютекс з успадкуванням пріоритету. Атрибут `osMutexPrioInherit` з лекції потрібен тільки для `osMutexNew`.

`estop` пише в лог після запису буфера. Якщо в цей момент `adc` передає рядок у UART, `estop` чекає на `uart_mutex` кілька мілісекунд. Світлодіод, переривання і `halted` до цього моменту вже змінено.

## Лог плати

ST-LINK перезапустив плату, перехідник CH340 записав лог. Лог записала перша версія прошивки на C++, до перенесення спільного коду в `common`. Кнопки натискала людина: 10 натискань повільно, 20 натискань швидко, потім KEY. Між серіями людина повернула потенціометр від краю до краю. Повний лог: [`serial.log`](serial.log).

| Показник | Результат |
|---|---|
| натискань кнопки-датчика до KEY | 30 |
| `parts` в останньому звіті | 30 |
| найбільша швидкість | 120,0 деталей/хв |
| напруга потенціометра | від 0 до 3319 мВ |
| від ISR до `estop` | 31 мкс |
| `estop` чекав на м'ютекс і писав буфер | 40 мкс |
| `report` зупинилась після KEY | через 65 мс, на своєму наступному звіті |
| `adc` зупинилась після KEY | через 574 мс, після таймауту `report_ready` |

Брязкіт кнопки не додав жодної зайвої деталі. Фрагмент лога, кінець другої серії і KEY:

```
I (132003) report: parts 28, rate 108.0/min; pot 1 mV
I (133003) report: parts 30, rate 120.0/min; pot 2 mV
I (136003) report: parts 30, rate 120.0/min; pot 0 mV
E (136936) report: SYSTEM HALTED!
W (136940) estop: parts 30, ISR -> estop 31 us, mutex 40 us
W (137001) report: conveyor halted, task stopped
W (137510) adc: conveyor halted, task stopped
```

Рядок `estop` має час на 4 мс пізніше за рядок `SYSTEM HALTED!`. Ці 4 мс `HAL_UART_Transmit` передавав рядок `SYSTEM HALTED!`.

## Запуск

1. Підключіть ST-LINK V2 до SWD-роз'єму плати.
2. Підключіть PA9 до RXD перехідника CH340, GND до GND.
3. Підключіть кнопку і потенціометр за таблицею підключення.
4. Прошийте плату:
   ```sh
   pio run -e stm32_conveyor -t upload
   ```
5. Відкрийте монітор порту:
   ```sh
   pio device monitor -e stm32_conveyor
   ```
