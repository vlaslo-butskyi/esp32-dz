# Спрощена технічна українська (СТУ)

Правила для технічних текстів у цьому репо: README, описів схем, інструкцій. Основа — ASD-STE100 Simplified Technical English. Розділи йдуть у тому самому порядку, що й у STE. Кожне правило перенесено на українську граматику. Правила, які в українській не мають сенсу (артиклі, форми на -ing), замінено на їхні українські відповідники.

Перевірка: `python3 tools/readme_lint.py <файл.md>`. Без аргументів скрипт перевіряє всі README.

## 1. Слова

**1.1. Використовуйте тільки дозволені слова.** Дозволені дієслова перелічено в розділі 10. Технічні назви наведено в розділі 11. Якщо потрібного слова немає, додайте його в словник з одним значенням.

**1.2. Одне слово — одне значення.** Слово «встановити» означає тільки «інсталювати» або «поставити на плату». Присвоєння значення позначає слово «задати».

**1.3. Одне поняття — одне слово.** Синонімів немає. Задача FreeRTOS — завжди «задача», а не «таск» чи «потік».

**1.4. Одне слово — одна частина мови.** Якщо дія записана дієсловом, її не перетворюють на іменник:

| Заборонено | Дозволено |
|---|---|
| виконати перевірку | перевірити |
| здійснює керування | керує |
| провести вимірювання | виміряти |
| відбувається перемикання | X перемикає Y |

**1.5. Без канцеляриту, кальок і жаргону.** Повний список — у розділі 12.

## 2. Іменникові ланцюжки

**2.1. Не більше трьох іменників підряд.** В українській мові ланцюжок утворюється з іменників у родовому відмінку: «значення затримки таймера обробника». Це вже чотири іменники.

**2.2. Розбивайте ланцюжок через дієслово або прийменник.** «Затримка, яку задає обробник для таймера» або «Обробник задає таймеру затримку».

## 3. Дієслова

STE дозволяє тільки прості часи й наказовий спосіб, а форми на -ing забороняє. В українській цьому відповідають такі правила.

**3.1. Дозволені форми:**
- наказовий спосіб для інструкцій: «підключіть»;
- теперішній час для описів: «ISR ставить прапорець»;
- минулий час для результатів: «аналізатор показав 12 фронтів»;
- майбутній час для наслідку: «світлодіод увімкнеться».

**3.2. В інструкціях — доконаний вид.** Доконаний вид описує дію з результатом: «натисніть», «підключіть». Недоконаний вид («натискайте») дозволено тільки для дії, яку повторюють або виконують протягом часу: «утримуйте BOOT».

**3.3. Без дієприслівників.** Українські дієприслівники (тримаючи, натиснувши) відповідають англійським формам на -ing. Дієприслівниковий зворот замініть окремим реченням або підрядним реченням з «коли» чи «після того як».

| Заборонено | Дозволено |
|---|---|
| Утримуючи BOOT, натисніть RST. | Утримуйте BOOT. Натисніть RST. |
| Перевіривши лог, відключіть аналізатор. | Перевірте лог. Потім відключіть аналізатор. |

**3.4. Без активних дієприкметників на -учий, -ючий, -ачий, -ячий.** Ці форми — кальки. Замість «працюючий таймер» пишіть «таймер, який працює».

**3.5. Активний стан.** Підметом є той, хто виконує дію. В інструкціях пасив заборонений. В описах його треба уникати.

| Заборонено | Дозволено |
|---|---|
| Таймер запускається функцією `timerBegin()`. | `timerBegin()` запускає таймер. |
| Прапорець скидається в `loop()`. | `loop()` скидає прапорець. |
| Пін має бути підключений до GND. | Підключіть пін до GND. |

Форми на -но, -то («виміряно», «підключено») дозволено тільки в описах і тільки тоді, коли виконавець дії неважливий.

## 4. Речення

**4.1. Одна думка — одне речення.**

**4.2. Довжина.** Речення в інструкції має не більше 16 слів. Речення в описі має не більше 20 слів. У STE межі становлять 20 і 25 слів. Українське речення коротше за англійське приблизно на п'яту частину, бо в ньому немає артиклів і допоміжних дієслів. Тому межі в СТУ нижчі.

**4.3. Прямий порядок слів:** підмет, присудок, додаток. Українська мова дозволяє вільний порядок слів, але в технічному тексті він заборонений. Обставину часу або умови ставте на початок речення.

**4.4. Не пропускайте службові слова.** У STE є правило не пропускати артиклі. В українській мові його відповідник — не писати телеграфним стилем. Прийменники, сполучники й займенник «який» пишіть повністю.

## 5. Інструкції

**5.1. Одна дія — один крок.** Кожен крок — окремий пункт нумерованого списку. Дві дії в одному кроці дозволено тільки тоді, коли їх виконують одночасно.

**5.2. Звертання на «ви», наказовий спосіб:** «Підключіть кабель». Форму інфінітива («Підключити кабель») не використовуйте, бо вона не показує, хто виконує дію.

**5.3. Спочатку умова, потім дія.** «Якщо порт не видно, замініть кабель».

**5.4. Спочатку пояснення, потім дія.** Якщо крок треба пояснити, напишіть пояснення окремим реченням перед кроком.

## 6. Описи

**6.1. Абзац — до 6 речень і одна тема.** Перше речення абзацу називає тему.

**6.2. Спочатку загальне, потім деталі.** Спершу напишіть, що робить модуль. Потім напишіть, як він це робить.

**6.3. Перелік із трьох і більше елементів** оформлюйте як вертикальний список або таблицю.

**6.4. Результати замірів подавайте без першої особи.** Підметом є прилад або сигнал: «Аналізатор зафіксував 7 фронтів за 1.2 мс». Цифри подавайте таблицею.

## 7. Попередження

**7.1. Сигнальне слово:** **ПОПЕРЕДЖЕННЯ** — коли є ризик для людини; **ОБЕРЕЖНО** — коли є ризик для обладнання. Для довідкової інформації без ризику використовуйте **ПРИМІТКА**.

**7.2. Попередження стоїть перед кроком,** якого стосується.

**7.3. Перше речення — коротка команда.** Друге речення пояснює причину:

> **ОБЕРЕЖНО:** не подавайте 5 В на GPIO. Пін ESP32-S3 витримує не більше 3,3 В.

## 8. Пунктуація, числа, одиниці

**8.1. Числа записуйте цифрами.**

**8.2. Дробову частину відокремлюйте комою** за українською нормою: «3,3 В», «10,06 мс». Крапку залишайте тільки в коді й у цитатах з логів.

**8.3. Між числом і одиницею ставте пробіл.** Одиниці пишіть українськими позначеннями СІ: «мс», «мкс», «В», «мА», «Ом», «кГц». Латинські позначення (`ms`, `V`, `Ω`) залишайте тільки в коді.

**8.4. Одна вставка на речення:** одні дужки або одне тире-уточнення. Дужки всередині дужок заборонені.

**8.5. Тире між підметом і присудком** ставте тільки за правилами правопису. Тире не замінює кому чи двокрапку для ефекту.

## 9. Структура документа

**9.1.** Документ починається з одного-двох речень про те, що він описує.

**9.2.** Кожен розділ відповідає на одне питання: що це, як підключити, як зібрати, які результати.

**9.3.** Без вступів, переказів і висновків, що повторюють текст.

**9.4.** Великі таблиці замірів і графіки виносьте в окремий файл (`analysis/README.md`), а в головному документі дайте на нього посилання.

## 12. Заборонені слова

| Заборонено | Дозволено |
|---|---|
| даний, дана, дане | цей, ця, це |
| являється, являє собою | є |
| шляхом | через |
| з метою | щоб |
| в якості | як |
| у випадку якщо, у разі якщо | якщо |
| на протязі | протягом |
| є можливість | можна |
| слідуючий | наступний |
| вірний (= правильний) | правильний |
| приймати участь | брати участь |
| по замовчуванню | за замовчуванням |
| варто зазначити, важливо розуміти, слід підкреслити | (видаліть) |
| ключовий, потужний, елегантний, надійний | (замініть числом або фактом) |

Також заборонено:
- emoji в тексті;
- риторичні запитання;
- конструкція «не X, а Y» частіше ніж раз на документ;
- жирний шрифт на початку кожного пункту списку.

## 13. Перед комітом

1. Запустіть `python3 tools/readme_lint.py <файл.md>`.
2. Виправте всі помилки (`ERR`).
3. Перегляньте кожне попередження (`WARN`). Якщо речення можна розбити, розбийте його.
4. Перевірте кожну інструкцію: один крок — одна дія, умова на початку.
